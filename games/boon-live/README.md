# ลานบุญ LIVE · โบสถ์แห่งศรัทธา

เกมแนวตั้งสำหรับขึ้นจอ TikTok Live / OBS ธีมโบสถ์แดงทอง พระประธาน ตัวละครชุดขาวเดินไปไหว้พระ ป้ายชื่อผู้ชม ของถวาย อันดับ และมหาพิธีแสงทอง ตัวเกมใช้ Python 3 ตัวเชื่อม TikFinity ใช้ Node.js 22 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

## เปิดเกม

ดับเบิลคลิก START.bat แล้วรอเบราว์เซอร์เปิดที่ http://127.0.0.1:8765 เซิร์ฟเวอร์ทำงานเบื้องหลัง ตัวเปิดจะตรวจว่าเกมพร้อมก่อนเปิดหน้าเว็บ ถ้ามีปัญหา ดู server-error.log

ใส่ชื่อแล้วกดของถวาย หรือใช้ปุ่ม 1–8 ขณะไม่ได้พิมพ์ชื่อ แต่ละกิจกรรมจะเพิ่มคะแนนและส่งตัวละครชื่อผู้ชมเดินไปไหว้พระ เมื่อถวายครบ 100 ครั้ง จะมีมหาพิธีแสงทองประมาณ 8.5 วินาที ปุ่ม “ดูตัวอย่างมหาพิธี” ใช้ดูเอฟเฟกต์โดยไม่เพิ่มคะแนน ปุ่มเดโมส่งชื่อและกิจกรรมจำลองทุก 1.7 วินาที กดซ้ำเพื่อหยุด

คะแนนเก็บในหน่วยความจำ รีเฟรชหน้าเว็บยังคงคะแนนเดิม เริ่มเซิร์ฟเวอร์ใหม่จะเริ่มรอบใหม่

## OBS

เพิ่ม Browser Source: http://127.0.0.1:8765/?overlay=1 ขนาด 1080 × 1920 เปิดหน้าควบคุมอีกแท็บหนึ่ง แต่ละหน้ารับ event พร้อมกัน ปุ่มตัวอย่างมหาพิธีแสดงเฉพาะหน้าที่กด ส่วนมหาพิธีจากการถวายครบเป้าหรือกิจกรรม grand แสดงทุกหน้าจอที่เชื่อมต่อ

## ช่องรับกิจกรรม TikTok

มีตัวเชื่อม TikFinity Desktop ใน tikfinity-bridge.mjs แล้ว เปิดด้วย START.bat พร้อมเกม ตัวเชื่อมฟัง ws://127.0.0.1:21213/ และส่งของขวัญที่จับคู่แล้วไป http://127.0.0.1:8765/api/event โดยไม่ต้องกรอกรหัสผ่าน TikTok ลงในเกม

### ตั้งค่าครั้งแรก

1. ติดตั้งและเปิด TikFinity Desktop (ไฟล์ TikFinity-Setup-2.0.0.exe ที่ดาวน์โหลดมา)
2. เข้าสู่บัญชี TikFinity ตามหน้าจอโปรแกรม แล้วเปิด Setup
3. ใส่ชื่อผู้ใช้ TikTok หลัง @ จากหน้าโปรไฟล์ ชื่อที่แสดง เช่น หมูเฮง อาจไม่ใช่ชื่อผู้ใช้
4. เริ่มไลฟ์ช่องของคุณ แล้วกด Connect to TikTok LIVE ใน TikFinity เปิดโปรแกรมค้างไว้
5. ดับเบิลคลิก START.bat ของเกม แล้วเปิด http://127.0.0.1:8765/?v=8
6. หน้าเกมต้องแสดง “เชื่อมต่อ TikFinity Event API แล้ว” หมายถึงเชื่อมกับโปรแกรมสำเร็จ ยังไม่ใช่หลักฐานว่า TikFinity เชื่อมไลฟ์สำเร็จ จนกว่าจะได้รับ event
7. เปิด “เชื่อมของขวัญ TikFinity / จับคู่กิจกรรม” ตรวจรายการของขวัญที่รับมาแล้ว ปรับชื่อหรือ ID ให้ตรง จากนั้นกดบันทึก

### การจับคู่เริ่มต้น

Rose → ตักบาตร, Finger Heart → สังฆทาน, Rosa → ผ้าไตร, Perfume → ถวายยา, Doughnut → เติมน้ำมัน, Paper Crane → พระไตรปิฎก, Hand Heart → บูรณะโบสถ์, Galaxy → กฐิน

ชื่อเหล่านี้เป็นค่าตั้งต้น ไม่ใช่การรับรองว่าช่องของคุณมีของขวัญครบทุกแบบ เมื่อมี event ให้ใช้ gift ID จริงแทนชื่อเพื่อให้ตรงกับภาษาหรือภูมิภาค ของขวัญที่ยังไม่จับคู่จะแสดงในรายการ แต่ไม่เพิ่มคะแนน การเปลี่ยน mapping มีผลกับ event ใหม่ ไม่ย้อนหลัง

การจับคู่บันทึกใน gift-map.json ตัวเชื่อมตรวจสถานะได้ที่ http://127.0.0.1:8766/status และจะลองเชื่อม TikFinity ใหม่ทุก 4 วินาที ถ้าเกมรับ event ไม่สำเร็จจะแสดงข้อผิดพลาด ไม่ส่ง HTTP ซ้ำอัตโนมัติเพื่อป้องกันคะแนนซ้ำ

สำหรับคอมโบแบบ giftType=1 จะรอ repeatEnd ก่อนส่งยอดสุดท้าย และใช้ groupId/msgId กัน event ซ้ำในหน่วยความจำ ถ้าต้นทางไม่มีรหัสเหล่านี้จะไม่สามารถยืนยัน event ซ้ำได้ครบถ้วน การเริ่ม bridge ใหม่จะล้างประวัติรหัสที่เคยรับ ไม่มีการ replay ของขวัญเก่าอัตโนมัติ

### ส่ง event เข้าเกมโดยตรง

| action | กิจกรรม | แต้มต่อครั้ง |
|---|---|---:|
| incense | ตักบาตร | 1 |
| temple | ถวายสังฆทาน | 5 |
| tree | ถวายผ้าไตร | 10 |
| fruit | ถวายยารักษาโรค | 20 |
| lamp | เติมน้ำมันตะเกียง | 30 |
| lantern | ถวายพระไตรปิฎก | 99 |
| bell | ร่วมบูรณะโบสถ์ | 100 |
| grand | ทอดกฐินสามัคคี | 1000 |

คีย์ lantern/tree/temple ยังใช้ได้ แต่คะแนนปรับตามตารางใหม่เพื่อให้ตรงรูปแบบของถวายในเกม

```powershell
$body = @{ action = 'temple'; name = 'ผู้ชม'; count = 1 } | ConvertTo-Json
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/api/event' -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

count เป็นจำนวนเต็ม 1–100, name สูงสุด 40 ตัวอักษร bridge ควรจัดการนับของขวัญต่อเนื่องและป้องกัน event ซ้ำก่อนส่ง จำนวนแต้มและกิจกรรมจะนับครบตาม count แต่จำกัดตัวละครที่สร้างต่อ event ไม่เกิน 4 และตัวละครพร้อมกันไม่เกิน 6 เพื่อความลื่นไหล

ทุกแต้มและของถวายเป็นสิ่งสมมติ ไม่มีระบบรับเงินหรือบริจาคจริง เซิร์ฟเวอร์เปิดเฉพาะเครื่องนี้ (127.0.0.1)

## ฉากเวอร์ชัน 6

โบสถ์หินสีงาช้าง เสาหยกเขียว พระประธานบนฐานดอกบัว แสงเช้าจากหน้าต่าง และทางเดินหินแทนพรมแดง ภาพฉากแดงทองเดิมสำรองเป็น temple-red-gold.png ใช้ระบบและเลย์เอาต์เดิม


## กิจกรรมเวอร์ชัน 7

กิจกรรมทั้ง 8 แบบมีเอฟเฟกต์ต่างกัน: ตักบาตรมีข้าวลงบาตร สังฆทานเป็นตะกร้าของใช้ ผ้าไตรเป็นผ้าพับและริ้วสีจีวร ถวายยามีกล่องยาและหัวใจ น้ำมันตะเกียงมีเปลวไฟและแสงอุ่น พระไตรปิฎกเป็นคัมภีร์กับหน้ากระดาษ บูรณะโบสถ์มีกรอบแสงรอบอาคาร และกฐินมีป้ายกฐินสามัคคีพร้อมแสงทอง

คีย์ action ใน API และคะแนนคงเดิมตามตารางด้านบน ชื่อภาษาอังกฤษเป็นรหัสเดิมเพื่อให้ event bridge ที่ตั้งไว้ยังใช้ได้

## ท่ากราบเวอร์ชัน 9

ใช้ภาพท่าทาง 4 เฟรมจริงจาก pilgrim-bow.png: ยืน → คุกเข่า → วางมือ → กราบถึงพื้น → กลับมาคุกเข่าและยืน เล่นประมาณ 5.6 วินาที ไม่ใช้การย่อหรือบีบภาพตัวละครเพื่อทำท่ากราบ ป้ายชื่ออยู่ชั้นแยกและขนาดคงเดิม

ปุ่ม “ดูท่ากราบ” ทดลองแอนิเมชันเฉพาะหน้าที่เปิด โดยไม่เพิ่มคะแนนหรือส่งของขวัญจริง แอตลาสภาพฝังใน CSS เพื่อไม่ต้องหยุดเซิร์ฟเวอร์ไลฟ์ที่กำลังทำงาน


## รูปของขวัญเวอร์ชัน 10

ปุ่มของขวัญ ป้ายเหนือตัวละคร รายการกิจกรรม และแผงประกอบกิจกรรมใช้ภาพของขวัญจาก TikTok CDN ที่เก็บใน gift-icons/ และฝังใน CSS เพื่อให้เปิดได้โดยไม่ต้องโหลดรูปจาก CDN ระหว่างไลฟ์ กิจกรรมทำบุญและคะแนนเดิมยังเหมือนเดิม

แสดงชื่อของขวัญ จำนวนเหรียญอ้างอิง และกิจกรรมคู่กัน ตรวจอ้างอิงรายการรูปใน gift-icons/catalog.json ภาพเป็นของ TikTok/เจ้าของสิทธิ์ ไม่ใช่ภาพที่สร้างด้วย AI

รูปจะเปลี่ยนตามชื่อหรือ ID ในการจับคู่ TikFinity สำหรับของขวัญที่มีใน catalog นี้ ถ้าตั้งเป็นของขวัญที่ยังไม่มีรูปใน catalog จะใช้รูปกล่องของขวัญกลางแทน ไม่แสดงภาพของขวัญเดิมที่ไม่ตรงกัน


## การอ่านบนจอไลฟ์เวอร์ชัน 11

ขยายชื่อของขวัญและชื่อกิจกรรม ใช้ชื่อไทยและพื้นหลังทึบเพื่อเพิ่มความต่างสี ป้ายชื่อผู้ชมใหญ่ขึ้น แถบกิจกรรม 2 บรรทัด อันดับผู้เล่นแสดง 3 คน และตัวละครพร้อมกันสูงสุด 6 คน จัดสองคอลัมน์เพื่อไม่ให้ป้ายชื่อทับแถบของขวัญ การอ่านบนไลฟ์จริงยังขึ้นกับขนาดจอและ UI ของ TikTok ที่ซ้อนอยู่


## เสียงอวยพรเวอร์ชัน 12

เปิดหน้าเกม แล้วกด “เปิดเสียงอวยพร” หรือ “ทดลองฟัง” ในแผงเสียง ระบบใช้ SpeechSynthesis และเสียงภาษาไทยที่เบราว์เซอร์/อุปกรณ์มี ไม่ใช่บริการเสียง AI แบบเสียเงิน และไม่ต้องใช้ API key คุณภาพและรายชื่อเสียงขึ้นกับอุปกรณ์ หากไม่พบเสียงไทย จะแจ้งในหน้าเกมและไม่เปิดเสียงผิดภาษา

คำอวยพรเรียกชื่อผู้ส่งและเปลี่ยนตามกิจกรรม มีตัวเลือกไม่อ่านชื่อ ความดัง ความเร็ว และเลือกเสียง รวมกิจกรรมชื่อเดียวกันที่รอในคิวและไม่พูดทับกัน หากกิจกรรมมาก คิวเต็มจะรวมคำขอบคุณผู้ร่วมบุญแทนเพื่อไม่ให้เสียงค้างนาน

ทุกหน้าเริ่มปิดเสียง ต้องกดเปิดหนึ่งครั้งหลังโหลดหน้า ปุ่มทดลองฟังไม่เพิ่มคะแนน เลือกเปิดเสียงเฉพาะหน้าที่ใช้จับเสียงขึ้นไลฟ์ หน้า OBS มีปุ่มเปิดเสียงมุมขวาบน ต้องโต้ตอบกับหน้า Browser Source เพื่อกดเปิดเสียง และตรวจแหล่งเสียงในโปรแกรมสตรีมด้วย

เปิดเสียงหน้าเดียวเพื่อป้องกันเสียงซ้ำ แท็บที่ใช้เบราว์เซอร์และต้นทางเดียวกันจะสั่งปิดเสียงอีกแท็บให้อัตโนมัติ แต่เบราว์เซอร์คนละโปรแกรมหรือ OBS อาจไม่แชร์ช่องสื่อสารนี้ หากใช้ Desktop Audio จะต้องจับเสียงของเบราว์เซอร์ที่กำลังพูดได้จริง หากแชร์หน้าจอมือถือ ต้องตรวจว่าระบบแชร์เสียงภายในด้วย ไม่รับรองว่าเสียง Web Speech ถูกบันทึกในทุกอุปกรณ์

ทดสอบระบบคิวด้วย `node --test blessing-voice.test.mjs` ครอบคลุมการรวมคอมโบ ชื่อไทย ไม่พูดทับ ปิด/ล้างคิว ปฏิเสธ autoplay และเบราว์เซอร์ที่ไม่มีระบบเสียง การได้ยินเสียงจริงต้องใช้ปุ่มทดลองฟังบนอุปกรณ์ที่จะไลฟ์

อ้างอิง API: https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis


## เพลงคลอเวอร์ชัน 13

เพลง “แสงเช้าในลานบุญ” เป็นดนตรีบรรเลงจากโน้ตและ oscillator ที่กำหนดขึ้นสำหรับโปรเจกต์นี้ ไม่ใช้ไฟล์เพลงสำเร็จรูปหรือ sample ของผู้อื่น กดเปิดเพลงในแผงเพลงคลอ ปรับความดังได้ และมีปุ่มเปิดเพลงในหน้า OBS ด้วย

เริ่มต้นปิดเพลง ต้องกดเปิดหลังโหลดหน้า เมื่อมีเสียงอวยพร เพลงจะลดเหลือ 20% ของความดังที่ตั้งไว้แล้วคืนระดับเดิมเมื่อพูดจบ ปิดการลดเสียงอัตโนมัติได้ เพลงและเสียงอวยพรควรเปิดจากหน้าเดียวกับที่ระบบไลฟ์จับเสียง เบราว์เซอร์คนละโปรแกรมหรือ OBS อาจไม่แชร์สถานะเสียงข้ามหน้ากัน

รายละเอียดทำนองและแหล่งเสียงอยู่ใน MUSIC.md ไม่มีการโหลดเพลงจากเว็บไซต์เพลงภายนอก ทดสอบ engine ด้วย `node --test original-music.test.mjs blessing-voice.test.mjs` การฟังและการรับเสียงในไลฟ์จริงต้องทดสอบที่เครื่องที่ใช้งาน


## HTTPS ผ่าน ngrok สำหรับ LIVE Studio

เปิด START.bat แล้วเปิด NGROK_START.bat เพื่อรับลิงก์ HTTPS จากนั้นคัดลอกลิงก์ใน LIVE_URL.txt ไปใส่ Link Source ของ LIVE Studio ตั้งขนาด 1080 × 1920

ngrok ชี้ไปที่ overlay_gateway.py บนพอร์ต 8767 ซึ่งอนุญาตเฉพาะ GET ของหน้าเกม รูป CSS JavaScript และสถานะ/กิจกรรมสด บล็อก POST/PUT/PATCH/DELETE และไฟล์อื่น หน้า public ใช้โหมด overlay ส่วนการส่งกิจกรรม ตั้งค่า TikFinity และทดสอบยังทำผ่าน localhost:8765 ตามเดิม

ผู้ใช้อนุญาตเปิดข้อมูลหน้าจอเกม ชื่อผู้ส่ง คะแนน และกิจกรรมของขวัญผ่านลิงก์สาธารณะแล้ว ผู้ที่มีลิงก์ดูข้อมูลนี้ได้ ngrok รุ่นใหม่อยู่ใน bin/ngrok.exe ใช้ config บัญชีเดิมที่ LOCALAPPDATA/ngrok/ngrok.yml โดยไม่คัดลอก authtoken มาไว้ในโปรเจกต์

แพ็กเกจฟรีแสดงหน้า Visit Site ก่อนเข้าผ่านเบราว์เซอร์ หากแหล่ง Link แสดงหน้านั้น ต้องยืนยันในเบราว์เซอร์/พรีวิวของแหล่งนั้น การเปิดผ่าน Chrome อีกตัวอาจไม่แชร์ cookie ให้ LIVE Studio

ลิงก์ใช้ได้เมื่อคอม อินเทอร์เน็ต เซิร์ฟเวอร์เกม gateway และ ngrok ยังทำงาน การปิดคอมหรือโปรแกรมจะทำให้ลิงก์หยุด และเปิดครั้งใหม่อาจได้ URL ใหม่ ปิดลิงก์สาธารณะด้วย NGROK_STOP.bat โดยไม่ปิดเกมภายในเครื่อง


## ลิงก์ Cloudflare เวอร์ชัน 15 — ใช้แทน ngrok

ngrok ปิดแล้ว เปลี่ยนมาใช้ Cloudflare Quick Tunnel แบบไม่ต้องสมัครบัญชีสำหรับลิงก์ HTTPS ชั่วคราว เปิด START.bat ก่อน แล้วเปิด CLOUDFLARE_START.bat คัดลอกลิงก์จาก LIVE_URL.txt ไปใส่ Link Source ใน LIVE Studio ตั้งขนาด 1080 × 1920 ใช้ CLOUDFLARE_STOP.bat เพื่อปิดเฉพาะลิงก์สาธารณะ

ลิงก์นี้ยังใช้คอมเครื่องนี้รันเกม ไม่ใช่การย้ายเซิร์ฟเวอร์ขึ้นโฮสต์ถาวร ต้องเปิดคอม อินเทอร์เน็ต เกม ตัวเชื่อม TikFinity และ Cloudflare ค้างไว้ เมื่อหยุดและเปิด Cloudflare ใหม่อาจได้ลิงก์ใหม่

เนื่องจาก Quick Tunnel ไม่รองรับ SSE จึงเพิ่ม cloudflare_gateway.py ที่พอร์ต 8768 ใช้ SSE รับกิจกรรมจากเกมภายในเครื่อง แล้วเก็บคิวหมายเลขลำดับไม่เกิน 512 รายการ หน้าเว็บสาธารณะอ่านเป็นชุดผ่าน /api/poll ประมาณทุก 1 วินาที ป้องกันเล่นกิจกรรมเดิมซ้ำ ไม่เพิ่มคะแนนซ้ำ ระบบในเครื่องยังรับ SSE เหมือนเดิม ไม่มีการรีเซ็ตคะแนนระหว่างเปลี่ยนลิงก์

เมื่อเปิดหน้าใหม่ จะแสดงคะแนนปัจจุบันแต่ไม่เล่นแอนิเมชัน/เสียงของขวัญเก่าย้อนหลัง ถ้า gateway ถูกเริ่มใหม่ คิวเต็มระหว่างขาดการเชื่อมต่อ หรือ source ถูกเริ่มใหม่ จะปรับฐานไปสถานะปัจจุบันโดยไม่ replay ของขวัญเก่า คำขอแก้คะแนนและไฟล์ส่วนตัวผ่านลิงก์สาธารณะถูกบล็อก

ทดสอบด้วย `python -m unittest test_cloudflare_gateway.py` และ `node --test cursor-feed.test.mjs` เอกสารข้อจำกัด: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/


## มรรคทายกกล่าวขอบคุณ เวอร์ชัน 17

รูปแบบเริ่มต้นเป็นบทมรรคทายกงานบุญ: เรียกชื่อผู้ส่งและกิจกรรม กล่าวอนุโมทนา แล้วหมุนเวียนคำอวยพรสุขภาพแข็งแรง ความสุข และความอบอุ่นในครอบครัว เลือกคำลงท้ายครับ/ค่ะ/ไม่ลงท้ายได้ เลือกโหมดขอบคุณสั้นได้ เมื่อคิวมีหลายรายการจะใช้บทสั้นอัตโนมัติ

ยังใช้ SpeechSynthesis ของเบราว์เซอร์ ไม่ได้เรียกโมเดลสร้างข้อความหรือบริการเสียง AI ภายนอก จึงไม่มีค่า token จากฟีเจอร์นี้ น้ำเสียงจริงขึ้นกับเสียงภาษาไทยที่เบราว์เซอร์มี การปรับครั้งนี้เป็นรูปแบบบทพูด จังหวะ และระดับเสียง ไม่ใช่เสียงเลียนแบบบุคคล

ทดลองใน Chrome ผ่าน http://127.0.0.1:8765/?v=17#blessing-settings ใส่ชื่อทดลองแล้วกดทดลองฟัง ไม่เพิ่มคะแนนและไม่ต้องส่งของขวัญจริง


## มรรคทายกพูดวนเวอร์ชัน 18

เปิด Chrome ไปที่ http://127.0.0.1:8765/?v=18#blessing-settings แล้วกด “เปิดพูดวนสร้างบรรยากาศ” จะเริ่มบทต้อนรับทันทีแม้ยังไม่มีของขวัญ สลับ 6 บทโดยไม่แต่งชื่อผู้ส่งหรือแกล้งแจ้งว่ามีคนส่งของขวัญ เลือกเว้นช่วง 10/20/30/45 วินาทีหลังพูดจบได้ ค่าเริ่มต้น 20 วินาที

ของขวัญจริงมีลำดับก่อนบทสร้างบรรยากาศ: หยุดบทต้อนรับที่กำลังพูด ขอบคุณผู้ส่งของขวัญตามคิว แล้วกลับมาพูดวนหลังเงียบครบช่วงที่ตั้งไว้ ปุ่มปิดพูดวนหยุดเฉพาะบทสร้างบรรยากาศแต่ยังขอบคุณของขวัญ ปุ่มหยุด/ล้างคิวหรือปิดเสียงจะหยุดโหมดวนด้วย

ใช้เสียงของเบราว์เซอร์เดิม ไม่มีการเรียกโมเดลภายนอกและไม่ใช้ token ในฟีเจอร์นี้ เปิดเสียงเพียงหน้าเดียวที่ระบบไลฟ์จับเสียงได้


## ชวนกดติดตามเวอร์ชัน 19

โหมดพูดวนมี 9 บท รวมคำชวนกดติดตาม 3 แบบ สลับทุกบทที่ 3 ระหว่างคำต้อนรับและคำอวยพร บทชวนติดตามใช้คำสุภาพ ไม่ผูกกับการส่งของขวัญ ระบบของขวัญจริงยังขัดจังหวะบทสร้างบรรยากาศได้ตามเดิม


## ฉากแดงทองพร้อมพระสงฆ์ เวอร์ชัน 20

กลับมาใช้ฉากแดงทองเดิม เพิ่มพระสงฆ์ 3 รูปนั่งบนอาสนะข้างฐานพระประธาน เก็บทางเดินกลางไว้ให้ตัวละครเดินกราบ ภาพใหม่เก็บใน temple-red-gold-monks.png และใช้ temple-bg.png เป็นภาพในเกม ฉากงาช้างสำรองใน temple-ivory.png ภาพสร้างด้วย image_gen ตาม prompt ใน ART_PROMPTS.md


## ผู้ร่วมไหว้พระในฉาก เวอร์ชัน 21

เพิ่มผู้ร่วมไหว้พระเป็นภาพประกอบช่วงล่าง 8 คน แบ่งสองฝั่งของพรม เว้นทางเดินกลาง โดยยังมีพระสงฆ์ 3 รูปและพระประธานเดิม คนในภาพเป็นฉากประกอบคงที่ ไม่ใช่รายชื่อผู้ส่งของขวัญ ตัวละครและป้ายชื่อจากกิจกรรมจริงยังแสดงแยกตามเดิม เก็บภาพใหม่ใน temple-red-gold-congregation.png ใช้ image_gen ตาม prompt ใน ART_PROMPTS.md
